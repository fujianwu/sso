关于本项目

一个从零搭建的 SSO 认证系统，记录从想法到落地的完整过程。

项目背景

这是一个个人开发的单点登录（SSO）平台，起因是我在同时维护几个小工具和服务时， 每个都要单独处理登录逻辑，重复且难以维护。于是决定自己造一个轮子， 顺便深入理解 OAuth 2.0 的工作原理。

整个系统从 2025 年 12 月初开始动工，到 2026 年 1 月基本成型， 此后持续打磨细节——修 Bug、加功能、改界面，一直迭代到现在。 麻雀虽小，但 SSO 该有的核心能力都有：OAuth 2.0 授权码流程、MFA、 异常登录检测、多会话管理、管理员后台，一个不少。

开发历程
2025 年 12 月初
项目启动 用 FastAPI + SQLite 搭起基础框架，实现最简单的邮箱密码登录和 session 管理。 定下整体架构方向：纯后端渲染的 Jinja2 模板 + REST API 双轨并行。
2025 年 12 月中旬
OAuth 2.0 核心完成 实现完整的授权码流程（Authorization Code Flow），支持 client_id / client_secret 注册、scope 精细化控制、access token 与 refresh token 管理。 写了第一版 Python SDK 和 Flask 接入示例。
2025 年 12 月下旬 — 2026 年 1 月
安全能力堆叠 陆续加入 TOTP 多因素认证（MFA）、设备指纹信任机制（30 天免验证）、 异常登录检测（IP 变化、UA 异常触发强制 MFA）、审计日志、 手机验证码登录、多会话管理与强制下线。
2026 年 1 月 — 至今
持续迭代 补全管理员后台功能（用户管理、应用审计、自定义字段、白名单控制）， 重构前端界面，修复 Cookie 安全属性，优化限流和性能监控。 一边用一边改，目前运行稳定。
技术栈

选型原则是轻量、够用、不过度工程化。

Python 3.11 FastAPI SQLite Jinja2 bcrypt PyJWT pyotp (TOTP) OAuth 2.0 Lucide Icons
设计理念
安全优先

从 Cookie 属性到密码策略，每个细节都尽量安全。没有银弹，但能做的都做。

接入简单

提供 Python SDK 和完整文档，接入一个新应用的成本尽量压到最低。

自己用得上

所有功能都是因为自己需要才加进来的，不做没用的。功能少但每个都管用。
